# 집필 규칙

책(`book/`)을 쓰거나 고치는 모든 AI가 따른다. 결정의 근거는 [편집 결정 대장](decisions.md)에 있다.

## 1. 독자와 수준
- 기본 독자는 AI를 처음 배우는 사람이다. 각 장은 [curriculum](curriculum.md)에 적힌 수준에 맞춘다.
- 수준 L1~L5의 정의는 독자도 보도록 [책의 「읽는 법」](../book/README.md#읽는-법)에 둔다. 수준별로 쓰는 도구는 다음과 같다.

| 수준 | 설명 도구 |
|---|---|
| L1 입문 | 그림·비유·표. 수식을 쓰지 않는다 |
| L2 기초 | 간단한 수식과 손으로 따라 할 수 있는 계산 |
| L3 중급 | 수식, 동작하는 PyTorch 코드 |
| L4 고급 | 논문 인용, 설계 선택의 비교표 |
| L5 전문가 | 사례 분석, 판단 기준과 그 대가 |

- 한 장 안에서 수준을 올릴 수 있다. 그 부분은 절 제목 끝에 「(심화)」를 붙여 건너뛸 수 있게 한다.

## 2. 대화 답변
책이 아니라 사용자 질문에 대화로 답할 때의 규칙이다.
- 합니다체로 쓴다(ED-05).
- 짧은 답을 첫 문장에 둔다. 예·아니오 질문이면 예·아니오부터.
- 둘 이상을 구분하는 질문은 표로 답한다(무엇 | 어느 기준 | 뜻).
- 「공식 용어인가, 관례인가, 특정 논문·도구·프로젝트가 정한 것인가」를 가려 준다.
- 사용자가 자기 작업 맥락(학습 로그, 지표, 모델 구성)을 주면 일반 개념을 먼저 설명하고 그 맥락에 대입한다.
- 답 끝에 책 반영 결과(바꾼 장·절) 또는 반영 위치 제안을 한두 줄로 붙인다.

## 3. 책 본문 문체
- 해라체(「~다」)로 쓴다(ED-05). 한 문장에 한 생각, 문장은 짧게.
- 일반 독자에게 쓴다. 「질문하신」「우리 프로젝트」「앞서 말씀드린」처럼 특정 대화·사람을 가리키지 않는다.
- 시점을 가리키는 말(「최근」「요즘」「새로 나온」)을 쓰지 않는다. 빨리 바뀌는 사실(최신 모델, 최고 성능 수치)이 꼭 필요하면 「(2026년 기준)」처럼 기준 시점을 적는다.
- 과장하지 않는다. 「혁명적」「완벽한」「항상」 대신 조건과 범위를 쓴다.

## 4. 장 구조
[장 템플릿](templates/chapter.md)으로 시작한다. 순서는 다음과 같다.

1. 제목: `# 5.2 정밀도·재현율·F1` — 장 번호와 제목은 curriculum과 글자까지 같게
2. 메타 줄: `> **수준** L2 · **선수** [5.1 평가 설계의 기본](05-01-evaluation-design.md) · **이 장의 질문** …`
3. `## 한눈에` — 3~5줄 요약. 이것만 읽어도 핵심을 말할 수 있게
4. 본문 절 `## 1. …`. 개념 하나는 기본적으로 「왜 필요한가 → 직관(그림·비유) → 정의 → 숫자 예시 → 수식(수준에 따라) → 한계와 함정」 순서로 쓴다
5. `## 헷갈리기 쉬운 점` — 해당할 때
6. `## 정리`
7. `## 확인 문제` — 3~5개. 답은 `<details>`로 접는다
8. `## 더 읽을거리` — `[@키]` 인용

초고 상태의 장은 1~3과 쓴 절만 있어도 된다. 검토완료·확정 장은 6·7까지 갖춘다(검사기가 확인한다).

강조 상자는 굵은 라벨을 단 인용 블록으로, 다음 네 가지만 쓴다.

| 상자 | 쓰는 곳 |
|---|---|
| `> **핵심**` | 꼭 기억할 한 가지 |
| `> **주의**` | 자주 하는 오해와 실수 |
| `> **표준과 관례**` | 공식 정의, 관례값, 특정 맥락의 정의를 가를 때 |
| `> **현업 사례**` | 개념을 실제 작업에 대입한 예(§8) |

## 5. 용어 표기
- 처음 나올 때 `한국어(English, 약어)`로 쓰고, 그다음부터 한 가지 표기만 쓴다. 예: 정밀도(precision), 교차 엔트로피(cross-entropy).
- 업계에서 영어 그대로 쓰는 말은 영어로 쓴다. 예: Transformer, attention, epoch, batch, backbone, head, prompt. 억지 번역어를 만들지 않는다.
- 한국어 번역어가 둘 이상의 원어에 겹치면 원어를 늘 붙인다. 예: 규제(regularization)와 정규화(normalization).
- 표기의 정본은 [용어집](../book/appendix/glossary.md)의 「표기」 칸이다. 새 용어를 쓰면 같은 작업에서 용어집에 넣는다.
- 용어집 「분류」 칸에는 다음 값만 쓴다: 분야 · 구조 · 과제 · 방식 · 학습신호 · 규모·활용 · 학습과정 · 평가 · 데이터 · 수학 · 시스템.

## 6. 수식·코드·그림·표
- 수식은 `$…$`(문장 안), `$$…$$`(따로 한 줄)로 쓴다. 수식 전에 말로 먼저 설명하고, 수식 바로 뒤에 모든 기호의 뜻을 적는다.
- 코드는 Python 3과 PyTorch로, 그대로 실행되는 최소 예제로 쓴다. 필요한 import를 맨 위에 둔다.
- 그림은 Mermaid 코드 블록 또는 `book/figures/`의 SVG로 둔다. 그림 아래에 한 줄 설명을 단다. 외부 링크(아티팩트·이미지 URL)에만 있는 그림에 기대지 않는다(ED-04).
- 비교·구분은 표로 한다. 표 중간에 빈 줄을 넣지 않는다. 표 칸 안에 `|`를 쓰지 않는다.
- 숫자 예시는 손으로 따라 할 수 있는 작은 값으로 하고 계산 과정을 보여 준다.

## 7. 인용과 출처
- 참고문헌은 [references.md](../book/appendix/references.md) 한 곳에 둔다. 본문에서는 `[@Vaswani2017]`처럼 키로 인용하고, 여러 개는 `[@He2016; @Dosovitskiy2021]`처럼 쓴다.
- 키는 첫 저자의 성 + 연도다. 같은 키가 있으면 끝에 a, b를 붙인다.
- 항목 형식: `- **@키** · 저자. 「제목」. 학회·저널·출판사, 연도. URL 또는 DOI`
- URL이나 DOI가 없는 문헌은 싣지 않는다(ED-10). 확인하지 못한 문헌은 [미확인 목록](open-questions.md)으로 보낸다.
- 1차 출처(원 논문, 공식 문서)를 우선한다. 블로그와 요약 글은 보조로만 쓴다.
- 수치는 출처와 측정 조건(데이터셋·지표·설정)을 함께 쓴다. 조건이 다른 수치를 나란히 비교하지 않는다.

## 8. 현업 사례
- 실제 프로젝트의 상황은 개념을 대입해 보는 「현업 사례」 상자로만 쓴다(ED-11).
- 일반화해서 쓴다. 예: 「자동차 손상 사진에서 부품과 손상을 찾는 검출 모델」. 내부 결정 번호, 폴더·파일 경로, 비공개 데이터와 사진, 사람·회사를 알아볼 수 있는 정보는 넣지 않는다.
- 사례의 수치는 개념을 설명하는 예시로만 쓰고 성능 주장으로 쓰지 않는다.

## 9. 파일과 경로
- 경로는 영문 소문자·숫자·하이픈으로 쓰고(ED-06), 제목과 본문은 한국어로 쓴다.
- 부 폴더는 `partNN-슬러그`, 장 파일은 `NN-MM-슬러그.md`다. 예: `book/part05-evaluation/05-02-precision-recall-f1.md`. 경로는 curriculum의 「파일」 칸이 정본이다.
- 링크는 상대 경로로 건다. 다른 장의 특정 절을 가리킬 때는 절 앵커까지 건다.

## 10. 금지
`book/`에 다음을 쓰지 않는다. 검사기(`tools/book.py check`)가 일부를 잡지만, 잡히지 않아도 규칙은 지킨다.
- 대화체, 특정 대화·사람을 가리키는 말
- 작업 경위, 변경 이력, 날짜 기록(§3의 기준 시점 표기는 제외)
- 작성자·AI 이름, 작성일·수정일
- TODO·TBD·FIXME 같은 미완 표시 — 미확인 목록이나 `workbench/`로 보낸다
- 확인하지 않은 문헌·수치
