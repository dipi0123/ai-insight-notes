# 편집 결정 대장

확정된 편집 결정만 둔다. 다른 문서는 결정을 다시 풀어 쓰지 않고 `ED-xx`로 가리킨다. 결정을 새로 만들거나 바꿀 때는 사용자 승인을 받고 이 표를 먼저 고친다. 바뀐 결정은 그 자리에서 고쳐 쓰고 이전 내용을 남기지 않는다(이력은 git).

## 산출물과 정본
| ID | 결정 | 정본 문서 |
|---|---|---|
| ED-01 | 최종 산출물은 `book/`의 책 하나다. 확정된 기술 지식만 담고 대화·경위·작업 이력은 담지 않는다. 이력은 git이 맡는다. | [AGENTS.md](../AGENTS.md) |
| ED-02 | 모든 AI 공통 규칙의 정본은 `AGENTS.md`다. `CLAUDE.md`·`GEMINI.md`는 AGENTS.md를 불러오는 입구이며 규칙을 따로 두지 않는다. | [AGENTS.md](../AGENTS.md) |
| ED-03 | 프로젝트 지식(결정·용어·진행 상태)과 사용자가 준 교정·작업 방식은 저장소 파일에만 둔다. AI 도구의 개인 메모리에 두지 않는다. 한 AI의 메모리에만 있으면 다른 AI는 모른다. Claude Code의 자동 메모리는 프로젝트 설정(`.claude/settings.json`)으로 꺼 둔다. | [AGENTS.md](../AGENTS.md) |
| ED-14 | 책의 예제 코드는 최종 산출물의 일부로 `book/code/`에 두고, 그대로 실행되어야 한다. 본문에 적는 실행 결과는 실제로 돌린 값만 쓴다. | [style-guide §6](style-guide.md#6-수식코드그림표) |
| ED-04 | 책의 정본 형식은 Markdown이다. 수식은 LaTeX(`$`), 그림은 Mermaid 또는 `book/figures/`의 SVG로 둔다. 웹 사이트(ED-16)·HTML 페이지·아티팩트는 이 Markdown에서 만든 파생물이며, 파생물을 따로 고치지 않는다. | [style-guide §6](style-guide.md#6-수식코드그림표) |
| ED-15 | 책 이름은 저장소 이름과 같은 「AI Insight Notes」(`ai-insight-notes`)다. | [book/README.md](../book/README.md) |
| ED-16 | 책의 최종 형태는 웹 사이트다. 독자는 브라우저에서 읽는다. 사이트는 `book/`의 Markdown에서 생성하며, 사이트에만 있는 내용을 두지 않는다. | [AGENTS.md](../AGENTS.md#이-프로젝트) |
| ED-17 | 웹 사이트는 Zensical로 만들고 GitHub Pages로 펴낸다. 사이트 설정의 정본은 `tools/site/config.toml`이고, 사이트 목차는 `tools/book.py site`가 curriculum에서 만든다. 생성기에 맞춘 원고 변환(인용 링크 등)은 `tools/book.py`에 두어 생성기를 바꿔도 원고는 그대로 쓴다. | [workflow §8](workflow.md#8-웹-사이트) |

## 형식과 문체
| ID | 결정 | 정본 문서 |
|---|---|---|
| ED-13 | 독자는 소프트웨어 개발 경험은 있지만 AI는 처음인 개발자다. 소프트웨어 기초는 설명하지 않는다. 책의 도달점은 독자가 경량 언어 모델이나 CV 모델을 직접 설계·구축하는 것이다. | [AGENTS.md](../AGENTS.md#이-프로젝트) |
| ED-05 | 책 본문은 해라체(「~다」), 사용자와의 대화 답변은 합니다체로 쓴다. | [style-guide §2·§3](style-guide.md#3-책-본문-문체) |
| ED-06 | 파일·폴더 경로는 영문 소문자·숫자·하이픈으로, 제목과 본문은 한국어로 쓴다. 기술 용어의 표기는 ED-19를 따른다. | [style-guide §9](style-guide.md#9-파일과-경로) |
| ED-19 | 기술 용어는 영어 원어를 기본으로 쓰고 한국어 번역어는 괄호에 단다. 예: precision(정밀도). 공부하는 책이므로 독자가 논문·공식 문서·코드에서 만나는 이름을 그대로 익히게 한다. 책 본문·제목·용어집과 대화 답변에 모두 적용한다. | [style-guide §5](style-guide.md#5-용어-표기) |
| ED-07 | 장마다 수준(L1 입문 ~ L5 전문가)과 선수 장을 둔다. | [curriculum](curriculum.md) |
| ED-10 | 참고문헌은 `book/appendix/references.md` 한 곳에 두고 본문은 `[@키]`로 인용한다. URL이나 DOI가 없는 문헌은 싣지 않는다. | [style-guide §7](style-guide.md#7-인용과-출처) |
| ED-11 | 사용자가 하는 다른 프로젝트의 상황은 일반화한 「현업 사례」로만 쓴다. 내부 결정 번호·경로·비공개 데이터는 싣지 않는다. | [style-guide §8](style-guide.md#8-현업-사례) |

## 절차
| ID | 결정 | 정본 문서 |
|---|---|---|
| ED-08 | 장 상태는 계획 → 초고 → 검토완료 → 확정이다. 검토는 집필 AI와 다른 AI가, 확정은 사용자가 한다. | [workflow §0](workflow.md#0-장-상태) |
| ED-09 | 질문에 답한 뒤, 책에 들어갈 지식은 같은 작업에서 책에 반영한다. 사용자가 「반영 보류」라고 하면 반영하지 않는다. | [workflow §1](workflow.md#1-질문-응답과-책-반영) |
| ED-12 | 부·장의 신설·삭제·순서·제목 변경과 편집 결정 변경은 사용자가 정한다. AI는 제안만 한다. 장 안의 절 구성은 AI가 정한다. | [workflow §7](workflow.md#7-구성-변경) |
| ED-18 | 한 세션에 끝나지 않거나 다른 AI에게 넘기는 작업은 `workbench/progress/`의 진행 기록 파일 하나로 넘긴다. 작업이 끝나면 오래 쓸 결론만 정본 문서로 옮기고 파일은 지운다. | [workflow §9](workflow.md#9-긴-작업의-진행-기록) |
