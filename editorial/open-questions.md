# 미확인 목록

책에 넣기 전에 확인이 필요한 주장·문헌·논쟁점을 한 줄씩 둔다. 확인되면 책에 반영하고 그 줄을 지운다. 틀린 것으로 확인되면 그 줄만 지운다([작업 절차 §6](workflow.md#6-미확인-항목)).

- ID는 `OQ-` + 세 자리 번호이고, 지운 번호는 다시 쓰지 않는다.
- 「확인 방법」에는 무엇을 보면 가려지는지 적는다(원 논문의 어느 절, 공식 문서 등).

| ID | 확인할 것 | 관련 장 | 확인 방법 |
|---|---|---|---|
| OQ-001 | 1955년 Dartmouth 제안서(@McCarthy1955)가 「artificial intelligence」라는 이름을 처음 쓴 문서로 꼽히는지. 제안서 원문에는 그런 서술이 없어 1.1에서 뺐다 | 1.1 | AI의 역사를 다룬 교과서나 회고 문헌에서 이름의 기원 서술을 찾아 원문과 대조한다 |
| OQ-002 | AI에 하나로 합의된 엄밀한 정의가 없다는 서술의 근거. 1.1은 근거를 찾지 못해 이 문장을 빼고 AI 정의를 책의 작업 정의로만 밝혔다 | 1.1 | 여러 AI 정의를 비교하는 AI 개론 교과서의 해당 장을 받아 확인한다 |
| OQ-003 | Sculley2015 그림 1에서 모델 코드(ML Code)를 둘러싼 바깥 상자의 이름(설정·데이터 수집·데이터 검증·feature 추출·계산 자원 관리·분석 도구·작업 관리 도구·serving 인프라·모니터링이 맞는지) | 1.3 | NeurIPS 2015 proceedings PDF 4쪽 그림 1의 상자 글자를 사람이 읽어 대조한다(그림이 이미지라 본문 텍스트에 글자가 없다) |
| OQ-004 | 모델 이름을 붙이는 공식 분류 체계가 없다는 것을 직접 밝힌 문헌 | 1.2 | ISO/IEC JTC 1/SC 42 등 표준 기구의 AI 표준 목록과 범위 조항, 모델 명명 관행을 다룬 조사 논문을 확인한다 |
| OQ-005 | ISO/IEC 22989의 범위(Scope) 조항과, 이 표준이 모델 이름 짓기 규칙을 다루는지 | 1.2 | ISO 원문이나 공식 소개 페이지를 사람이 열어 본다(www.iso.org는 내려받기 도구에 HTTP 403을 돌려줌) |
| OQ-006 | 구조 이름(CNN·RNN·Transformer)과 task 이름(classification·detection·segmentation)이 교과서와 논문에서 거의 같은 뜻으로 쓰인다는 것 | 1.2 | 교과서 두세 권(예: Goodfellow 외 9장)과 대표 논문의 정의를 맞대어 본다 |
| OQ-007 | 모델 이름 꼬리(Instruct·Base)와 크기 표기(8B)가 공개 모델 저장소의 관례이고 정해진 규칙은 없다는 것 | 1.2 | 여러 계열(Llama·Qwen·Gemma 등)의 모델 카드에서 꼬리와 크기 표기를 비교하고, 명명 규칙을 밝힌 문서가 있는지 본다 |
| OQ-008 | Stable Diffusion v1 계열 autoencoder가 Rombach2022의 KL-reg.(VAE와 비슷한 정규화) 변형인지 VQ-reg. 변형인지. 확인되면 1.5장 §4.2에서 1.2장 §2.4의 VAE로 이을 수 있다 | 1.5 | CompVis/stable-diffusion 저장소의 v1 추론 설정 파일(first_stage_config)과 Rombach2022 §3.1을 대조한다 |
| OQ-009 | @Abadi2016(OSDI 2016 게재로 알려짐)과 @Kapoor2024의 학회 게재 여부. 받은 문서에서 확인하지 못해 참고문헌을 arXiv로 적었다 | 1.6 | 학회 프로시딩 페이지(OSDI 2016은 usenix.org, 허용 목록 밖)에서 확인하고 참고문헌 항목의 학회 표기를 고친다 |
