# 판정 — 지적을 채택·기각·미확인으로 가르기

자체 점검의 지적마다 채택할지 정한다. 지적과 해당 문장, 원문만 보고, 지적에도 주장과 같은 근거를 요구한다. 점검 렌즈나 집필 패스와 다른 에이전트가 한다. [공통 규칙](../README.md#모든-카드-공통)을 따른다.

## 입력
- 장 번호 `N.M`, 회차 `N`, 이번 회차의 `checks/rN-*.json`

## 읽을 것
- 지적 파일들, 문장 목록(`checks/rN-sentences.json`)
- 지적이 가리키는 문장의 `ledger.json` `refs`
- 근거로 든 원문(`fetch.py page`·`anchor`), 규칙 조항(style-guide·AGENTS.md의 해당 절), 실행 기록

## 쓸 것
- `build/harness/N.M/judge-rN.json`(형식은 [README](../README.md#점검과-판정-형식))

## 할 일
지적마다:
1. 지적의 근거를 직접 연다. 닻이 원문에 있는지, 조항이 정말 그렇게 말하는지, 실행 기록이 그 값을 보이는지.
2. 문장의 근거도 같은 방식으로 연다.
3. 정한다.
   - `채택`: 지적의 근거가 확인되고 문장이 틀렸거나 규칙을 어긴다.
   - `기각`: 지적의 근거가 없거나 틀렸고, 문장이 근거와 맞는다. 취향 차이도 기각한다.
   - `미확인`: 원문으로 가려지지 않는다. 그 문장은 책에서 빼고 미확인 목록으로 보낸다.
4. `reason`에 무엇을 열어 보고 그렇게 정했는지 한두 문장으로 적는다.

점검 렌즈가 놓친 문제를 새로 지적하지 않는다. 눈에 띄면 `note`로만 남긴다.

## 돌려줄 것
`{"status", "file": "build/harness/N.M/judge-rN.json", "accepted_blocking": <수>, "unresolved": <미확인 수>}` — `status`는 [공통 규칙 8](../README.md#모든-카드-공통)의 네 값 중 하나다.
