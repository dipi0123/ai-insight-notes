# 자체 점검: 검산·실행

숫자 예시를 다시 계산하고, 코드를 다시 돌린다. 집필 패스의 계산 기록을 믿지 않고 따로 계산한다. [공통 규칙](../README.md#모든-카드-공통)을 따른다.

## 입력
- 장 번호 `N.M`, 회차 `N`

## 읽을 것
- 문장 목록(`book.py sentences N.M --json`), stage의 장 파일과 코드
- `ledger.json`에서 계산·실행 문장의 `path`
- `book/code/requirements.txt`, 승인된 실험 계획(코드 장)

## 쓸 것
- `build/harness/N.M/checks/rN-calc.json`(`lens`는 `검산·실행`)
- 내 계산과 실행 기록: `build/harness/N.M/checks/calc-rN/`

## 할 일
1. 계산 문장마다 본문에 적힌 값으로 처음부터 다시 계산한다(작은 Python 스크립트를 `calc-rN/`에 두고 출력도 남긴다). 반올림과 단위까지 본다.
2. 갈래가 설명·연결인 문장에 숫자 계산이 숨어 있으면 그것도 검산한다.
3. 수식: 기호의 뜻이 모두 적혔나, 본문의 말과 수식이 같은 것을 말하나, 숫자 예시가 수식과 맞나.
4. 코드 장: 깨끗한 가상 환경(`calc-rN/venv`)에서 「준비물」대로 설치하고 돌린다. 본문의 출력·shape·실행 시간·실행 조건(하드웨어, 버전, seed)과 비교한다. 같은 seed로 두 번 돌려 결과가 같은지 본다.
5. 승인 목록 밖의 패키지·데이터·가중치가 필요하면 설치하지 않고 `사용자 결정 필요`로 돌려준다.

판정: 계산·실행 문장마다 `일치`·`불일치`·`미확인`. 지적의 근거는 내 기록 파일(`evidence.type: 실행`, `output`)이다.
