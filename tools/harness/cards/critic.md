# 반론 — 구성안 공격

구성안을 쓴 패스와 다른 에이전트가 한 번 공격한다. 구성안을 직접 고치지 않는다. [공통 규칙](../README.md#모든-카드-공통)을 따른다.

## 입력
- `build/harness/part-NN/plan.md`

## 읽을 것
- 구성안, 그리고 구성 패스가 읽은 것과 같은 범위([plan](plan.md)의 「읽을 것」)
- `AGENTS.md`의 「이 프로젝트」(독자·도달점·다섯 단계)

## 쓸 것
- `build/harness/part-NN/critique.md`

## 할 일
다음 관점에서 지적을 찾는다. 지적마다 `차단` 또는 `권고`와 근거(curriculum 행, 규칙 조항, 앞 장의 절)를 단다.
1. 절 구성이 「이 장의 질문」에 실제로 답하나.
2. 선수 범위 밖의 개념에 기대는 절이 있나. 같은 개념을 두 장이 본 장으로 맡거나, 아무 장도 맡지 않나.
3. 수준(L1~L5)과 분량(40분 안)에 맞나.
4. 이 부가 도달점(경량 language model이나 CV 모델을 직접 설계·구축)으로 가는 길에서 맡은 몫을 하나. 뒤 부가 기대는 개념을 빠뜨리지 않았나.
5. 학습 방법·성능 고도화 장(8~10·12부)이 방법을 이름과 절차가 아니라 구조로 설명하게 짜였나(AGENTS.md 원칙 6).
6. 출처 후보가 1차 출처인가. 블로그·요약 글에 기대는 사실이 있나.
7. 실험 계획이 노트북 CPU 몇 분 안에 돌 수 있나. 데이터·패키지의 라이선스가 분명한가.
8. 묶음 나눔이 §10.1을 지키나.
