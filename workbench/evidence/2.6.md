## 교차 검토 우선 목록
- 책이 고른 정리: GPU 고르는 기준의 순서(메모리 → dtype별 처리량 → memory bandwidth → 여러 장)는 한 문헌이 그대로 말하지 않는다(조사 gaps). §1 표·한눈에·정리·핵심 상자는 갈래 「설명」이다. 순서가 공정한지, 특히 memory bandwidth 행의 「자세히: 13.2장」 연결이 맞는지
- §1.1 학습 메모리 표는 Transformers 문서(GPU memory usage)의 parameter당 바이트(6·8·4)를 그대로 옮겼다. 혼합 정밀도의 weight 6바이트와 fp32 gradient 4바이트를 한 표에 둔 조합이 문서의 조건과 맞는지, 「40억 × 2바이트 = 8GB, 그 열 배 넘게」(계산)가 85GB 어림(f42)과 조건이 같은 비교인지
- §1.2 TF32: 「NVIDIA Ampere 이후 GPU의 TF32라는 연산 형식」은 PyTorch CUDA semantics 절 제목에서 온 표현이고 TF32의 정의는 쓰지 않았다. A100 약 7배(f66)는 문서 예제 수치다. 「dtype 사이의 속도 차이는 GPU 세대마다 다르다」로 일반화한 것이 TF32·FP32 비율(f65)의 범위를 넘지 않는지
- §2 Azure 문서의 번역: Stopped(Allocated)·Deallocated의 과금, spot VM의 회수 조건, pay-as-you-go를 「일반 요금」으로 옮긴 것. spot VM을 「클라우드의 남는 용량을 크게 할인된 값에」로 일반화해 첫 문장에 Azure를 밝히지 않은 곳(절 머리와 「표준과 관례」 상자로 Azure 기준이라 밝혔다)
- §3 근거 없는 설명 문장: 「CUDA GPU가 있는 기계라면 torch만은 설치 안내에서 그 기계의 CUDA에 맞는 같은 버전의 빌드를 고른다」, 「GPU driver가 설치됐는지, PyTorch가 CPU 전용 빌드로 설치되지 않았는지를 차례로 확인한다」, 헷갈리기 표의 「driver가 깔려 있어도 PyTorch가 CPU 전용 빌드면 GPU를 쓰지 못한다」. driver·CUDA 호환 규칙은 허용 목록 안 문서가 없어 쓰지 않았다(미확인 제안)
- §4.4 struct 형식 문자(「<는 little-endian, Q는 64비트 부호 없는 정수」)는 Python 표준 라이브러리 문서가 대장에 없어 갈래 「설명」이다. 「같은 파일을 다시 요청하면 내려받지 않고 캐시의 경로를 돌려준다」도 설명이다
- §4.4 실행 해석: down_proj의 (576, 1536)을 (out, in)으로 읽은 것은 calc.txt의 nn.Linear in_features·out_features로 받쳤다. 「마지막 normalization weight」는 tensor 이름(model.norm.weight)에서 읽은 것이다. 출력 layer가 파일에 없는 까닭을 tie_word_embeddings(f92)와 calc.txt의 data_ptr 일치로 받쳤다
- §5.1 Wolf2020의 「transformer는 index를 contextual embedding으로」를 「문맥이 반영된 embedding」으로 옮겼다. tokenizers 라이브러리 문장은 「논문 시점(2020년)」으로 한정했다(설치판 5.24.1의 동작은 확인하지 않았다)
- §5.2 「image 열을 풀려면 Pillow 패키지가 있어야 해서」는 실행 오류 메시지(block-c-decode.txt)로만 받쳤다. 「split='test'만 요청했는데 train Parquet까지 받아졌다」는 이 판(datasets 5.2.0)과 이 저장소의 실행 결과이고 일반 규칙으로 쓰지 않았는지
- §5.3 표와 끝 문단(라이브러리가 가리는 것, 이 책이 5.8·8.6·14.3에서 직접 짜는 까닭)은 책의 방침을 말한 설명이다

## 미확인으로 보낸 것
- GPU driver 버전과 CUDA runtime 버전의 호환 규칙, PyTorch CUDA wheel이 runtime을 함께 담는지 — NVIDIA 문서가 허용 목록 밖이라 미확인으로 보냈다
