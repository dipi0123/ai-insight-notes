## 교차 검토 우선 목록
- 책 고유의 분류: 다섯 층(§2 표·Mermaid·「표준과 관례」 상자 s-616af8~s-14996e). 다섯 층을 받치는 표준 1차 출처는 없어 「설명」으로 두었다(조사 gaps 1). 층 이름·경계(특히 클라우드 API를 serving 층에 둔 것 s-ca71c2)가 타당한지
- 교과 판정: accelerator 정의(s-9bcd64)는 Paszke2019의 「hardware accelerators such as GPU」와 Goodfellow2016 §12.1.6의 특수 하드웨어 문장을 묶은 정리다. inference server 정의(s-622bcb)는 Kwon2023의 weight 메모리·batching 문장을 묶은 정리다
- s-750da2·s-c5a5fe·s-a59247·표 s-4faad7~s-1d1fca: 「API 모델」은 이 책이 고른 이름이다. Kapoor2024는 closed, Solaiman2023은 cloud/API access라 부른다. 표의 API 쪽 칸 가운데 「받지 못한다」「개발사 서버」는 정의 수준이라 따로 근거를 달지 않았다(조사 gaps 4)
- s-6fd5be·s-837255·s-c1ec90: API fine-tuning은 시점에 묶인 사실이다(2024-01 Kapoor2024, 2026-11 OpenAI2026). 다른 개발사 문서는 받지 않았다. 표 칸의 「개발사가 서버에서 fine-tuning을 해 주기도 하지만」이 OpenAI 한 곳의 사례로 일반화한 것이 아닌지
- s-ea1b30(표)·s-c5659c·s-116777: BERT·GPT-3·SAM을 foundation model 층의 예로 둔 것. BERT·GPT-3는 Bommasani2021이 예로 들지만, SAM은 논문이 「foundation model을 목표로 삼았다」는 것까지만 받친다(1.5에서 인용)
- 비유와 번역어: §1 소프트웨어 스택 비유(s-060219·s-e80b6e), adaptation(적응), accelerator(가속기), inference server(추론 서버), 「곱셈-누산기」(Jouppi2017의 MAC), 「메모리 대역폭」(Goodfellow2016의 memory bandwidth)
- s-4722dc: Goodfellow2016의 「같은 layer의 뉴런을 서로 독립적으로 처리」를 layer라는 낱말 없이 「많은 계산 단위를 서로 기다리지 않고 따로 계산」으로 풀었다. 뜻이 넓어지지 않았는지
- s-847de2·답 3(s-fe5b35~s-a7560d): 「weight만 공개하면 세 요구 가운데 Parameters 하나를 채운 셈」은 OSI2024 정의를 대입한 책의 판단이다. Parameters 요구도 OSI 승인 조건(f91)을 요구하므로 라이선스에 따라 그 하나도 못 채울 수 있다
- s-608f8a·s-182334: 층 하나를 바꿔도 위가 그대로 돈다는 설명은 Goodfellow2016 §12.1.2(같은 프로그램을 CPU·GPU에서)를 칩 층에만 받쳤다. 「API 모양이 같으면 응용 코드는 크게 바뀌지 않는다」는 근거 없는 설명이다
