## 교차 검토 우선 목록
- 교과 판정: §4.2의 grad_fn 이름 나열(PowBackward0→SubBackward0→MulBackward0→AccumulateGrad)은 실행 기록(code-j)만으로 받쳤고, AccumulateGrad의 역할은 쓰지 않았다. 그림(Mermaid)이 backward 점선에 ∂L/∂r·∂L/∂u·∂L/∂w를 단 것이 autograd 내부 동작을 과하게 단순화하지 않았는지
- 책이 고른 방식: device 고르기는 torch.accelerator(공식 Tensors 튜토리얼, f65)를 썼다. 이 API에 Stable·Unstable 표시가 없다는 조사 gaps 1을 본문에 쓰지 않았다. 「표준과 관례」 상자에서 CUDA semantics의 cuda 관용구(f81)와 나란히 둔 서술이 공정한지
- f70 해석: 「current_accelerator(check_available=True) or torch.device('cpu')」 한 줄은 check_available=True일 때 쓸 수 없으면 None을 돌려준다는 해석에 기댄다. 문서는 「컴파일 시점에 없으면 None, check_available=True면 실행 시점 확인을 더한다」까지만 쓴다. 이 기계에서는 mps가 나와 None 분기는 실행으로 확인하지 못했다
- 출처 판 차이: MPS float64 미지원(s-… §5.3, 정리)은 PyTorch 2.15 문서(f83)와 2.11 실행 기록(code-p)으로 받쳤다. 참고문헌 @PyTorch2026은 2.11 문서라 2.15 문서 인용을 어떻게 적을지 통합 때 정해야 한다. 본문은 「PyTorch 2.15 버전의 MPS backend 문서」라고 밝혔다
- CUDA 문서를 MPS로 넓힌 곳: 「연산 결과가 입력 tensor와 같은 장치에 놓인다」(f75), 0차원 tensor 예외(f63)는 CUDA 문서·예시다. 본문은 각각 「CUDA semantics 문서는 … 쓰고, 위 실행에서도」 「문서의 예는 CUDA이고, MPS에서도 같다는 것은 위 실행으로 확인」으로 갈랐다. MPS의 비동기 실행은 쓰지 않았다(§5.5는 CUDA 문서와 장치별 동기화 함수까지만)
- 설명 문장 중 근거 없는 것: §4.4 「이 누적을 일부러 이용하는 기법이 4.8장의 gradient accumulation이다」, §6 「u ** 2의 derivative 2u를 구하려면 u가 필요해서 autograd는 u를 저장해 둔다」, §2.2 「다른 언어에서 부분 배열을 잘라 내면 새 배열이 생기는 데 익숙하다면」, §5.5 「작은 계산을 GPU로 옮긴다고 빨라지지는 않는다」(timing-all 범위 안의 일반화인지)
- 번역어: dtype(데이터 타입), device(장치), view(뷰), copy(복사본), seed(시드), autograd(자동 미분)·automatic differentiation(자동 미분) 두 용어가 같은 한국어를 쓴다. view·copy는 용어집 후보에 없어 행을 넣지 않았다
- 시간 측정의 결론: CPU thread 6개(torch.get_num_threads 기본값)에서 잰 CPU 시간이다. 1024에서의 배율이 실행마다 흔들릴 수 있다(세 번 2.38~2.48배). 결론 문장(s-정리 마지막, 한눈에 마지막)이 실행 기록 범위를 넘지 않는지

## 미확인으로 보낸 것
- torch.accelerator API의 release status(Stable/Unstable): 2.11·2.15 문서 페이지에 표시가 없다. 본문은 안정성을 주장하지 않고 공식 튜토리얼의 방식으로만 썼다
- MPS에서 연산이 비동기로 실행되는지를 직접 쓴 PyTorch 문서: 본문은 쓰지 않았다
