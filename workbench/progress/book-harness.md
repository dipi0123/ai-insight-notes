## 목표

## 현재 상태
- 준비 단계의 도구와 역할 카드가 갖춰졌고, 수용 시험(`python3 -I tools/harness/selftest.py`)이 109개 모두 통과한다.
- 규칙 문구(ED-20, 미정 Q-01, workflow §10, AGENTS.md의 패스 경계 규칙 등)는 사용자가 승인했고 커밋했다.

- 시범 운영 1(심은 오류 시험)을 마쳤다. 심은 오류 7개를 모두 잡았고 대조 문장에 헛지적이 없었다. 결과는 [회귀 시험의 기준선](../../tools/harness/regression/README.md#기준선)에 있다.
- 시범 운영 2(1.1~1.4 소급 자체 점검)를 마쳤다. 묶음 `batch-01-1`에서 1.1·1.3·1.4를, 보류했던 1.2는 사용자 결정대로 묶음 `batch-01-2`에서 한 번 더 고쳐 통합했다. 네 장 모두 상태는 `초고 · Claude`다(자체 점검은 교차 검토가 아니다).
- 시범 운영 3(1.5·1.6을 구성부터 부 리뷰까지)을 진행 중이다. 1부 구성안(`build/harness/part-01/plan.md`)을 사용자가 승인했고(결정 D1~D4), 1.5를 묶음 `batch-01-3`으로 혼자 먼저 써서 통합했다. 사용자가 1.5를 L1 이론 기준 장으로 승인했다. 1.6은 `batch-01-4`에서 보류됐다가 사용자 결정대로 `batch-01-5`에서 다시 돌려 통합했다. 1부 부 리뷰와 읽기 안내(`build/harness/part-01/review/`)를 마쳤고, 지적을 사용자 결정대로 모두 반영해 다시 통합했다(`batch-01-6`: 1.5, `batch-01-7`: 1.1·1.3·1.4·1.6). 사용자 요청으로 커밋하고 push했다(`156ce4f`). 시범 운영 측정값은 아래 「시범 운영 측정값」에 있다.
- 「운영에서 고칠 것」 반영과 직역투 정리는 사용자 요청으로 커밋하고 push했다(아래 두 항목).

## 시범 운영 측정값
설계안 11절이 재기로 한 값이다. 토큰은 워크플로가 알린 하위 에이전트 토큰(입력 포함)이고, 시간은 워크플로의 기계 시간이다.

**검출과 헛지적.** 시범 운영 1(심은 오류)은 [회귀 시험의 기준선](../../tools/harness/regression/README.md#기준선)에 있다. 심은 오류 7개를 모두 잡았고, 대조 문장을 틀렸다고 한 지적은 없었다. 시범 운영 2·3에서 1.1~1.6의 판정 파일을 모두 모으면 다음과 같다.

| 렌즈 | 등급 | 채택 | 기각 | 미확인 |
|---|---|---|---|---|
| 출처 대조 | 차단 | 30 | 0 | 17 |
| 출처 대조 | 권고 | 76 | 4 | 0 |
| 검산·실행 | 권고 | 4 | 1 | 0 |
| 설명 | 차단 | 39 | 1 | 0 |
| 설명 | 권고 | 102 | 16 | 0 |

- 지적은 모두 290개다. 판정은 채택 251, 기각 22, 미확인 17로 갈랐다. 기각 비율(헛지적)은 약 8%이고, 차단 지적만 보면 87개 중 1개다. 기각은 설명 렌즈의 권고에 몰려 있다(118개 중 16개). 판정이 「취향 차이」로 기각한 것들이다.
- 미확인 17개는 모두 소급 점검(1.1·1.2·1.3)의 출처 대조 차단 지적이다. 출처를 찾지 못한 문장들이라 OQ-001~OQ-007로 넘겼다. 새로 쓴 장(1.5·1.6)에서는 미확인이 0개다. 조사 패스가 먼저 출처를 모으기 때문이다.
- 장별 지적 수: 1.1 71, 1.2 69, 1.3 31, 1.4 61, 1.5 32, 1.6 26. 하네스 밖에서 쓴 장(1.1~1.4)이 새로 쓴 장보다 두 배쯤 많다.
- 1부 부 리뷰는 장 단위 렌즈가 놓친 장 사이 모순 1개(SFT 정의, 차단)와 권고 23개를 찾았다. 장마다 통과해도 부 리뷰가 필요하다.

**수정 회전.** 「일치가 아닌 문장」이 0이 되기까지 고친 횟수다. 부 리뷰 반영은 따로 셌다.

| 장 | 회전 | 부 리뷰 반영 |
|---|---|---|
| 1.1·1.3·1.4 | 2 | 1 (1.1·1.3·1.4) |
| 1.2 | 3 (두 번 뒤 보류, 새 묶음에서 한 번) | 없음 |
| 1.5 | 2 | 2 |
| 1.6 | 3 (두 번 뒤 보류, 새 묶음에서 한 번) | 1 |

- 세 번째 회전까지 간 두 번(1.2·1.6) 모두, 마지막에 남은 차단은 내용 오류가 아니었다. 1.6은 그림 노드에서 약어를 처음 풀 때 한국어가 빠졌다. 부 리뷰 반영에서 1.5에 남은 차단도 괄호 한국어를 다시 단 것이었다. 둘 다 style-guide §5의 표기 규칙이고, lint가 잡을 수 있는 종류다(Mermaid 노드 안의 첫 등장, 같은 장에서 괄호 한국어를 되풀이).
- 수정이 장을 늘린다. 1.5는 구성안 어림 12,500자에서 집필 뒤 14,334자, 부 리뷰 반영 뒤 15,558자가 됐다. 1.6은 13,499자에서 14,333자가 됐다.

**통합 충돌.** 묶음 시작과 통합 직전의 공유 파일 해시가 어긋난 적, merge가 거부한 적, 통합 뒤 check가 실패한 적이 모두 0번이다. 시범 운영 2에서 통합 check가 「인용하지 않는 참고문헌」 경고를 2건 냈고, 그 일로 `entry` 규칙을 만들었다.

**비용.** 시범 운영 3(1.5·1.6을 구성부터 부 리뷰까지)이다.

| 단계 | 에이전트 | 토큰 | 기계 시간 |
|---|---|---|---|
| 구성·반론·구성안 고침 | 3 | 약 46만 | 약 10분 |
| 1.5 (조사·집필·점검 3회차) | 16 | 약 228만 | 약 45분 |

- 새로 쓴 이론 장 하나에 에이전트 16~21개, 토큰 약 230만~250만, 35~45분이 들었다. 설계안 12절의 추정(이론 장에 에이전트 8~12개)의 두 배쯤이다. 부 단위 비용(구성·부 리뷰·반영)을 장 수로 나누어 더하면 더 커진다.
- 시범 운영 2(1.1~1.4 소급)는 에이전트 61개가 들었다. 회차 2·3과 1.2를 다시 돈 것에 하위 에이전트 토큰 약 815만이 들었고, 회차 1의 토큰은 기록하지 않았다.
- 사용자 접점: 구성안 결정 4개, 기준 장 승인 1번, 보류 뒤 다시 돌리기 1번, 부 리뷰 결정 3개, 용어집 기존 행 승인. 사용자가 장 하나를 읽는 데 든 시간은 재지 않았다.

**운영에서 고칠 것.** 사용자가 네 가지를 모두 반영하기로 했고, 반영했다.
1. `status` 값: [하네스 README 공통 규칙 8](../../tools/harness/README.md#모든-카드-공통)에 네 값을 글자 그대로 쓰고 다른 말(완료·수정완료·ok)을 쓰지 않는다고 적었다. 오케스트레이터는 결과 스키마의 `status`를 enum으로 둔다. 카드 14장의 「돌려줄 것」에서 이 규칙을 가리킨다.
2. 표기 lint(`tools/book.py` 2026.11.2): Mermaid 블록 안의 글도 첫 등장으로 센다. 첫 등장 뒤 표 밖에서 괄호 한국어를 다시 달면 후보로 알린다. 표 행 안에서 같은 줄에 단 풀이는 첫 등장의 풀이로 친다.
3. 분량: 13,500자를 넘는 장은 lint 경고를 낸다(오류가 아니다).
4. 비용: [설계안 12절](../drafts/2026-11-25_claude_book-harness.md#12-규모-추정)의 추정을 실측으로 고쳤다. 남은 100장에 에이전트 2,200~3,000개, 토큰 3억~4억, 기계 시간 80~120시간.
- 수용 시험: 합병 시험의 가짜 장을 1.5에서 2.1로 옮겼다(1.5가 책에 들어와 깨졌다). lint 시험 3개를 더해 107개 모두 통과한다.
- 새 lint가 1부에서 찾은 것: 1.6 26행(Mermaid 노드)이 `inference server`의 첫 등장인데 「추론 서버」가 없었고, 88행에서 괄호 한국어를 달았다. 사용자 결정으로 풀이를 그림 노드로 옮겼다(장 해시 a11b4e64332f). 표기만 바뀌어 두 문장(s-2aa6dd 그림, s-5a3e95)의 갈래·근거·판정은 바뀌기 전 문장(s-bf79ca, s-622bcb)의 것을 그대로 옮겼고, 렌즈를 다시 돌리지는 않았다. 1.5(15,558자)·1.6(14,333자)은 분량 경고가 남았다. 줄일지는 사용자가 정한다.

**직역투 정리.** 사용자 지적(1.3 제목의 「한살이」가 직역이다. 독자는 소프트웨어 개발자이니 흔히 쓰는 말을 쓰고, 없으면 영어로 쓴다)에 따라 고쳤다.
- style-guide §5에 규칙 한 줄을 더했다(ED-19의 풀이라 결정 대장은 그대로다). 장 템플릿의 표 머리는 「헷갈리는 짝」에서 「헷갈리는 개념」으로 바꿨다.
- 1.3 제목: 「ML lifecycle: 데이터에서 서비스까지」(curriculum·toc·1.4·1.6 메타 줄). 용어집에 `ML lifecycle` 행을 더했다. 1.3 §1에 정의 문장 한 개를 더했다.
- 1부 전체에서 직역투 낱말을 바꿨다: 갈래·짝·판·꼬리·되풀이·견주다·걷어 내다·도우미 등. 하위 에이전트가 1.1~1.6에서 82곳을 찾았다. 그중 「모델의 틀」「빗대면」처럼 경계에 있는 것은 그대로 두었다. 1.4 §2.2와 1.2 §3.3, 1.5 §4.2의 제목이 바뀌었고, 앵커 링크도 맞췄다.
- 근거 대장: 바뀐 문장은 새 번호를 받았다. 낱말만 바뀐 문장(약 80개)은 바뀌기 전 문장의 갈래·근거·판정을 그대로 옮겼다. 새 정의 문장 하나는 집필자가 `설명·일치`로 두었다. 렌즈는 다시 돌리지 않았다. 여섯 장 모두 `validate --final` 오류 0이다.
- 재발 방지: `tools/book.py`(2026.11.3)의 lint가 직역투 낱말 목록(`LITERAL_KO`)을 후보로 알린다. 제목과 Mermaid도 보고, 링크 주소는 뺀다. 고치기 전 1부 원고에서는 걸렸고, 고친 뒤에는 0건이다. 설명 렌즈 카드(check-explain) 할 일 6에 「직역투」 항목을 더했다. 수용 시험은 109개다.
- 용어집 diffusion model 행의 「걷어 내며」를 사용자 승인으로 「제거하며」로 바꿨다. `tools/harness/regression/planted-1/`의 시험 장은 기준선을 지키려고 그대로 두었다.

## 실패한 접근
- Workflow 도구의 결과 파일(`.output`)은 순수 JSON이 아니라 감싼 형식이라 그대로 파싱되지 않았다. 에이전트별 결과는 실행 폴더의 `journal.jsonl`(type `result`, 라벨은 `started` 항목)에서 읽는다.
- 용어 첫 등장 검사를 대소문자 무시로 하면 고유 이름을 풀어 쓴 곳(「Language-Image Pre-training」)이 용어로 잡혔다. 일반 명사 용어는 문장 첫머리에서도 소문자로 쓰므로(style-guide §5) 대소문자를 가린다.
- lint가 자기 장의 stage만 보면 같은 묶음의 다른 장으로 가는 링크가 깨진 것으로 나왔다. `build/harness/*/stage`를 모두 찾는다.
- `ledger.py verdicts`가 처음에는 회차 하나의 점검만 받아 판정 칸을 덮어썼다. 회차 2를 넣으면 회차 1에서 일치였던 문장의 판정이 지워지고, 회차마다 같은 지적 번호(`F1` 등)가 겹쳤다. 모든 회차를 함께 받는 방식으로 고쳤다.
- 소급 대장의 셸 루프에서 zsh의 `set -- $spec`은 낱말을 나누지 않아 주소에 공백이 섞였고 `fetch.py`가 `http.client.InvalidURL`로 죽었다. 예외 처리에 넣고, 명령은 하나씩 적어 돌린다.
- 워크플로의 에이전트 하나가 API 연결 오류로 실패해도 같은 스크립트를 `resumeFromRunId`로 다시 돌리면 끝난 에이전트는 캐시에서 온다. 판정만 다시 돌았다(실패한 판정은 21분을 쓰고 끊겼다).
